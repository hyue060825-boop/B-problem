# Q3 多卡单模型训练验收报告

本次由一条联合优化轨迹产生模型，SFT、DAgger、PPO 均使用 PyTorch DDP/NCCL，物理 GPU 0–3。每个 rank 处理不同样本分片，同步梯度后执行同样的 Adam 步数；rank 0 保存统一 checkpoint。不按卡选模型，不平均独立训练权重。

## 等价性与故障测试

执行：

```bash
CUDA_VISIBLE_DEVICES='' scripts/run_python.sh -m pytest tests/test_q3_joint.py -q
```

CPU/Gloo 两 rank 使用同一 CandidatePolicy 初值，与集中全局加权 batch 的多次 Adam 更新对照，采用双精度区分算法误差与 softmax 公共偏置的单精度舍入。覆盖不同有效样本数、置信权重、2 次梯度累积、尾部占位及某 rank 完全无样本；集中参考同时验证非零 rank 的样本确实影响 rank 0 更新。参数容差 rtol=1e-6/atol=1e-7，Adam 状态 atol=1e-8。该测试通过，不代替实际 CUDA 四卡验收。

同一测试覆盖全部 rank 无数据的共同跳过、完整长短 PPO 回合、失败终止、可变候选、全局优势均值/方差、全局 KL 共同停止、单 rank 非有限数据导致共同失败，以及保存后从一个文件恢复参数和 Adam。SFT critic 以零损失连接计算图，多步不产生未完成 reduction。

更新目标为全局加权均值。每个全局 batch 的分母 $Z$ 是所有 rank、全部累积微批的真实权重和，各 rank 使用 $W\sum_iw_i\ell_i/Z$；DDP 平均梯度后得到集中目标。占位样本有可合法执行的候选但损失权重为零。所有 rank 执行同样的 microbatch 次序，在最后一个累积微批同步；梯度裁剪在同步之后。

## 实际四卡与恢复

smoke 在 `smoke_v2` 中真实执行，33 个样本分片为 [9,8,8,8]，每卡 batch=2、累积=2。首次 smoke 因日志字段重名失败，保留记录，修复后另开输出目录。成功运行在第一 epoch 后暂停，四卡共同恢复同一个 latest，参数和 Adam 摘要与暂停前逐字节一致，然后继续完成第二 epoch。恢复时摘要为 `20c9cc31ad8908c3be92952f9adeb1ada9d13fd87c65ddb29f3118f39397a6a2`。

证据：[smoke 日志](../runs/q3_joint_20260912/smoke_v2/sft_smoke/metrics.jsonl)。其中每次共同 optimizer step 记录参数及 Adam 状态 SHA256，初始化还比较各 rank 相同输入 logits 的最大绝对差。smoke 权重只用于功能验收，未参与正式模型择优。

四卡 smoke 命令：

```bash
CUDA_VISIBLE_DEVICES=0,1,2,3 scripts/run_torchrun.sh --standalone --nnodes=1 --nproc-per-node=4 \
  scripts/train_q3_joint.py --config runs/q3_joint_20260912/smoke_v2_config.json \
  --stage sft_smoke --resume runs/q3_joint_20260912/baseline.pt \
  --data runs/q3_joint_20260912/preflight_v2/rows.pt --stop-after 1
```

实际验证过的恢复命令：

```bash
CUDA_VISIBLE_DEVICES=0,1,2,3 scripts/run_torchrun.sh --standalone --nnodes=1 --nproc-per-node=4 \
  scripts/train_q3_joint.py --config runs/q3_joint_20260912/smoke_v2_config.json \
  --stage sft_smoke --resume runs/q3_joint_20260912/smoke_v2/latest.pt \
  --data runs/q3_joint_20260912/preflight_v2/rows.pt
```

checkpoint 包含统一模型、Adam、共同 global_update、阶段步数、每 rank RNG、父 checkpoint 哈希、候选版本、配置和源码 provenance。只需该文件即可恢复所有 rank，不存在待合并的分卡模型。global_update 是实际共同 optimizer.step 数，PPO 回合轮次另外记录，避免乘以 world_size。

## 正式阶段

正式第一轮 SFT 已完成：2699 个有效行，8 epochs、48 次共同 optimizer 更新；所有更新的参数及 Adam 摘要一致，四卡在 Q3 初始公开历史输入上的 logits 最大绝对差为 0。[正式 SFT 日志](../runs/q3_joint_20260912/sft_round1/metrics.jsonl)。第二轮 DAgger 聚合 5318 行、8 epochs、88 次共同更新，同步检查通过。两轮采用同一逻辑学生；每张卡不保存独立最佳模型。

PPO 的四卡 smoke 同样实际执行了两轮，中间暂停并从单个文件恢复，恢复前后参数/Adam 摘要一致，两轮全部完成。[PPO smoke](../runs/q3_joint_20260912/smoke_v2/ppo_smoke/metrics.jsonl)。正式 PPO 从验证集选中的同轨迹阶段快照开始；实际结束统计待补充。

相关代码为 [train_q3_joint.py](../scripts/train_q3_joint.py)、[joint_updates.py](../solution/rl/joint_updates.py)。显式 collective 时间单独记录，forward/backward 时间包含 DDP 内部通信，不能当作纯 GPU 计算时间或精确 NCCL 计时。为保证恢复后的 epoch 样本顺序，监督阶段每轮从规范数据顺序拷贝后使用恢复的 RNG shuffle，不依赖上一轮原地排序的副作用。
